# 노션 포트폴리오 디자인 및 구성 기획서

**Project:** Finance & Accounting Process Improvement Portfolio  
**Platform:** Notion  
**Implementation:** Antigravity + Notion CLI  
**Design Direction:** Minimal Editorial  
**Initial Scope:** 메인 페이지 1개 + 프로젝트 상세 페이지 1개

---

## 1. 기획 목적

재무·회계 실무 경험과 업무 개선 역량을 보여주는 취업용 포트폴리오를 노션으로 제작한다.

이 포트폴리오는 이력서에 기재한 경력과 담당 업무를 반복해서 나열하는 문서가 아니다. 실무에서 문제를 발견하고, 개선 방향을 설계하며, 엑셀과 자동화 도구를 활용해 해결책을 구현하는 사람이라는 점을 보여주는 것이 핵심이다.

### 핵심 메시지

**실무를 이해하고, 반복 업무를 개선하는 재무·회계 실무자**

### 제작 원칙

- 정보의 양보다 정보의 위계와 가독성을 우선한다.
- 장식적인 디자인보다 여백, 정렬, 타이포그래피로 완성도를 높인다.
- 실제 경험과 확인 가능한 자료를 바탕으로 콘텐츠를 구성한다.
- 프로젝트가 추가되어도 전체 디자인의 일관성을 유지한다.
- 노션에서 실제 구현 가능한 블록과 레이아웃을 활용한다.

---

## 2. 디자인 콘셉트

### Minimal Editorial Portfolio

첨부한 디자인 레퍼런스의 미니멀한 에디토리얼 스타일을 참고한다.

핵심 디자인 요소는 다음과 같다.

1. 흰색 바탕과 넉넉한 여백
2. 짙은 남색을 활용한 제목과 핵심 강조
3. 작은 영문 섹션 라벨과 큰 제목의 대비
4. 좌우 비대칭 레이아웃과 2열 구성
5. 얇은 구분선과 절제된 회색 영역
6. 텍스트와 실제 프로젝트 자료를 중심으로 한 구성

일반적인 노션 문서처럼 제목과 본문을 위에서 아래로 길게 나열하지 않는다. 각 영역의 역할을 명확하게 구분하고, 좌우 열을 활용해 정보가 한눈에 들어오도록 설계한다.

### 컬러 시스템

- Background: `#FFFFFF`
- Light Gray: `#F3F4F6`
- Primary Navy: `#26364A`
- Secondary Text: `#68717D`
- Accent Sage Green: `#6B9B91`

남색은 주요 제목과 핵심 요소에 사용한다. 회색은 구획을 나누거나 보조 정보를 표시하는 데 사용하며, 세이지 그린은 필요한 경우에만 제한적으로 적용한다.

### 타이포그래피

- 영문 섹션 라벨: 작고 간결하게
- 메인 제목: 크고 명확하게
- 섹션 제목: 메인 제목보다 작되 충분한 위계 확보
- 본문: 읽기 편한 길이와 간격 유지
- 보조 설명: 회색 계열로 구분

노션에서 글꼴을 자유롭게 지정하기 어려운 부분은 기본 제공 스타일을 활용한다. 지원되지 않는 폰트나 레이아웃을 무리하게 구현하려 하지 않는다.

## 3. 전체 페이지 구조

초기에는 메인 페이지와 프로젝트 상세 페이지를 각각 하나씩 제작한다.

### 페이지 구조

**MAIN — Finance & Accounting Portfolio**
- Profile
- Expertise & Skills
- Selected Projects

**PROJECT 01 — Online Sales Settlement Automation**
- Background
- Problem
- Approach
- Implementation
- Evidence & Status

메인 페이지는 전체 포트폴리오를 소개하고 프로젝트로 연결하는 역할을 한다. 프로젝트 상세 페이지는 특정 업무 문제를 어떻게 개선했는지 구체적으로 설명하는 역할을 한다.

초기 포트폴리오의 핵심 소개 영역은 3개로 구성한다. Profile, Expertise & Skills, Projects다. 이 세 영역을 각각 독립된 메인 페이지로 만들 필요는 없다.

## 4. 메인 페이지 레이아웃

### SECTION A. HERO / PROFILE

**목적:** 첫 화면에서 포트폴리오의 주제와 작성자의 업무 성향을 전달한다.

구성 요소:
- 작은 라벨: `FINANCE & ACCOUNTING / PORTFOLIO`
- 메인 제목: `Finance & Accounting`
- 핵심 소개 문장: `실무를 이해하고, 반복 업무를 개선하는 사람`
- 짧은 소개 문단

레이아웃:
- 제목과 소개 문장을 중심으로 넓은 여백 확보
- 제목은 왼쪽 정렬
- 불필요한 프로필 카드, 장식용 아이콘, 과도한 이모지 사용 금지
- 첫 화면에서 핵심 메시지가 명확하게 전달되도록 구성

소개 문단은 경력 전체를 요약하기보다 업무를 바라보는 관점과 개선 지향적인 태도를 설명한다.

### SECTION B. EXPERTISE & SKILLS

**목적:** 실무 역량과 도구 활용 능력을 한눈에 보여준다.

이 영역은 2열 레이아웃으로 구성한다.

**왼쪽 — ACCOUNTING & FINANCE**

회계·자금 업무에 대한 실무 이해를 설명한다.

- 회계 전표 및 증빙 검토
- 자금 현황 관리
- 정산 자료 대조와 차이 확인
- 세무 관련 업무 처리 경험
- 반복적인 실무 업무의 흐름과 검토 과정에 대한 이해

**오른쪽 — DATA & AUTOMATION**

실무에서 활용한 도구와 데이터 처리 능력을 설명한다.

- 엑셀을 활용한 데이터 정리와 검토
- SUM, AVERAGE, IF, MAX, MIN, ROUND, TRIM
- VLOOKUP, COUNTIF, LEFT, RIGHT, MID
- 매크로를 활용한 반복 계산 및 정렬 작업 개선

실제 활용 경험과 수준에 맞는 항목만 표시한다. 사용 경험이 불확실하거나 숙련도를 입증하기 어려운 기술은 추가하지 않는다.

디자인은 2개의 열을 활용하되, 모든 항목을 카드로 만들지 않는다. 짧은 설명과 적절한 여백으로 역량을 구분한다.

### SECTION C. SELECTED PROJECTS

**목적:** 실제 업무 개선 프로젝트로 자연스럽게 연결한다.

첫 번째 프로젝트:

**Online Sales Settlement Automation**

설명 문구:
온라인 매출 정산 과정에서 반복되는 데이터 정리와 계산 업무를 개선한 프로젝트.

구성:
- 프로젝트 번호 `01`
- 프로젝트명
- 한두 줄의 요약 설명
- 실제 화면이나 자료가 있다면 대표 이미지
- 프로젝트 상세 페이지로 연결되는 링크

프로젝트 영역은 제목과 설명을 중심으로 간결하게 구성한다. 대표 이미지가 준비되지 않았다면 임의의 화면을 만들지 말고 이미지 없이 구성한다.

## 5. 프로젝트 상세 페이지 레이아웃

### PROJECT 01 — Online Sales Settlement Automation

프로젝트 상세 페이지는 메인 페이지보다 구체적인 정보를 제공한다. 다만 긴 보고서처럼 보이지 않도록 각 섹션을 명확히 분리한다.

### A. PROJECT OVERVIEW

- 프로젝트명
- 프로젝트 유형: 업무 개선 / 정산 자동화
- 상태: 과거 업무 개선 경험과 현재 개발 중인 도구를 구분해 표시
- 한 줄 소개

프로젝트 상태는 실제 진행 상황을 확인한 후 확정한다.

### B. BACKGROUND

업무 배경을 설명한다.

온라인 매출 정산 자료를 확인하고 계산하는 과정에서 주문별 자료를 정리하고 금액을 대조하는 반복 작업이 발생했다.

실제 경험을 바탕으로 짧게 작성하며, 배경 설명이 길어지지 않도록 한다.

### C. PROBLEM

문제점을 2~3개로 요약한다.

- 정산 자료를 정리하고 이해하는 데 시간이 소요됨
- 주문별 금액 확인과 반복 계산이 필요함
- 수작업이 많아 처리 과정이 복잡함

문제는 실제 경험한 범위 안에서 설명한다. 발생하지 않은 오류나 손실을 임의로 추가하지 않는다.

### D. APPROACH

어떤 방식으로 개선했는지 설명한다.

- 정산 데이터를 엑셀로 정리
- 주문번호를 기준으로 데이터를 구분하고 계산
- 반복 계산과 정렬 작업에 매크로 활용
- 자동 처리 이후 결과를 확인하고 필요한 부분은 직접 검토

자동화가 모든 작업을 대체했다고 과장하지 않는다. 자동 처리 범위와 수동 검토 범위를 구분한다.

### E. IMPLEMENTATION

실제 개선 및 구현 과정을 보여준다.

사용 가능한 자료:
- 남아 있는 매크로 코드에서 확인 가능한 로직
- 실제 업무 처리 흐름에 대한 설명
- 현재 개발 중인 도구의 실제 화면
- 확인 가능한 데이터 처리 과정

과거에 사용한 매크로와 현재 개발 중인 도구는 동일한 프로젝트로 오해되지 않도록 구분한다. 실제 원본 화면이나 데이터가 없다면 재구성 화면을 실제 과거 화면처럼 제시하지 않는다.

### F. EVIDENCE & STATUS

프로젝트의 결과와 현재 상태를 설명한다.

- 확인 가능한 코드 또는 화면
- 실제로 구현된 기능
- 직접 확인한 결과
- 아직 검증되지 않은 부분

정확한 기록이 없는 과거 업무 소요 시간은 확정된 성과 수치로 표시하지 않는다. 사용자 피드백이나 외부 검증을 받지 않았다면 이를 받은 것처럼 표현하지 않는다.

## 6. 노션에서의 시각적 구현 원칙

Antigravity는 다음 디자인 규칙을 바탕으로 노션 페이지를 구성한다.

- 노션의 제목, 본문, 인용, 구분선, 열, 이미지, 하위 페이지 링크 등 지원되는 블록을 활용한다.
- 좌우 분할이 필요한 곳에는 노션의 열 기능을 사용한다.
- 제목과 본문의 크기 차이로 정보의 위계를 만든다.
- 회색 배경 블록은 핵심 정보를 구분할 필요가 있을 때만 사용한다.
- 표는 비교가 필요할 때만 사용하고, 단순한 설명은 짧은 문단으로 처리한다.
- 이모지는 의미가 있는 경우에만 제한적으로 사용한다.
- 이미지와 실제 프로젝트 자료가 들어갈 영역은 콘텐츠에 맞춰 배치한다.
- 모바일에서도 본문이 지나치게 복잡해 보이지 않도록 문단과 표의 길이를 조절한다.

노션의 기본 기능으로 구현할 수 없는 부분은 과도하게 우회하지 않는다. 디자인보다 가독성과 유지 관리 편의성을 우선한다.

## 7. 향후 프로젝트 확장 규칙

새로운 도구를 개발할 때마다 프로젝트 상세 페이지를 추가한다.

예시:
- Project 01 — Online Sales Settlement Automation
- Project 02 — 신규 업무 개선 도구
- Project 03 — 신규 업무 개선 도구

새 프로젝트는 기존 프로젝트 페이지를 템플릿으로 복제하고 다음 항목을 동일한 순서로 유지한다.

1. Project Overview
2. Background
3. Problem
4. Approach
5. Implementation
6. Evidence & Status

메인 페이지의 Selected Projects 영역에는 새 프로젝트 링크를 추가한다.

프로젝트마다 별도의 디자인을 만들지 않는다. 기존 레이아웃과 컬러, 제목 위계, 여백을 유지해 포트폴리오 전체의 통일성을 확보한다.

## 8. Antigravity 작업 지시

Notion CLI를 통해 노션과 실제로 연동되어 있다. 별도의 연동이나 인증 설정을 다시 진행하지 말고, 페이지 구조와 디자인 구현에 집중한다.

작업 순서:

1. 현재 노션에서 작업 대상 페이지를 확인한다.
2. 기존 콘텐츠를 무단으로 삭제하거나 덮어쓰지 않도록 작업 범위를 확인한다.
3. 메인 페이지의 Hero, Expertise & Skills, Selected Projects 레이아웃을 구성한다.
4. 프로젝트 상세 페이지 템플릿을 구성한다.
5. 노션 페이지에서 실제 렌더링 결과를 확인한다.
6. 열 배치, 여백, 제목 위계, 링크 연결을 점검한다.
7. 새 프로젝트를 추가할 때 재사용할 수 있도록 템플릿 구조를 유지한다.

실제 페이지에 반영하기 전에 수정 대상과 생성 위치를 확인하고, 기존 페이지의 중요한 내용을 보존한다.

## 9. 완료 기준

다음 조건을 만족하면 초기 포트폴리오 구조가 완성된 것으로 본다.

- 메인 페이지에서 포트폴리오의 성격과 핵심 메시지가 명확히 보인다.
- Profile, Expertise & Skills, Projects의 역할이 구분된다.
- 실무 역량과 엑셀 활용 능력이 한 영역에 정리되어 있다.
- 첫 프로젝트의 상세 페이지로 이동할 수 있다.
- 프로젝트 상세 페이지에서 문제, 개선 방향, 구현 과정, 근거 자료를 확인할 수 있다.
- 디자인은 미니멀한 에디토리얼 스타일로 통일되어 있다.
- 실제로 확인되지 않은 내용이나 성과가 들어가지 않는다.
- 새 프로젝트를 추가할 때 기존 디자인을 재사용할 수 있다.

**최종 목표:** 이력서의 내용을 반복하는 페이지가 아니라, 재무·회계 실무자가 업무를 분석하고 개선하는 사고 과정과 실제 구현 경험을 보여주는 확장 가능한 노션 포트폴리오를 만든다.
